# Anti-Slop audit 001 (2026-11-02)

Scope: the whole app: UI (`src/ui`), copy (`i18n.js`), styles, the logic and Apps Script code (`src`), the dev scripts, the docs.
Rules: miqdadbadjuber/anti-slop (R-01 to R-40, tiers: Hard Gate = HIGH, Purpose-Gate = MEDIUM, Quality Locks = LOW) and b4r7x/agent-skills anti-slop (code categories). The rule text was read through a summarising fetch, so rule numbers and meanings are cited, not quoted.
Method: 48 rendered screens (24 screens x phone and PC, demo data, headless Edge) measured for tap targets, overflow, focus visibility and decoration; axe-core in light and dark (earlier today: 0 problems); static checks over copy, CSS and code (`scripts/antislop-static.mjs`, `scripts/antislop-browser.mjs`); a manual read of the claims in the copy.
Not covered: real devices, a screen reader, the real data's long-tail screens, Quest Board and the other projects.

Nothing has been changed. Pick numbers to fix.

## What passed

- R-03 no horizontal overflow on any of the 48 screens.
- R-25 contrast: axe-core 0 problems in light and dark (4.5:1 text, 3:1 large).
- R-26 every one of the 82 rendered `data-action` controls has a handler.
- R-24 navigation: 5 tabs, all real.
- R-27 states: empty (Review), loading (skeletons), error (toasts, inline messages) exist.
- R-34 both themes work on every screen; R-19 motion is light (6 transitions, 2 keyframes) and `prefers-reduced-motion` is honoured.
- R-39 names, labels, alt text, ARIA: axe clean; cursors are pointers on controls.
- R-18, R-28, R-17 in marketing form: no testimonials, no FAQ, no invented statistics.
- R-10, R-13: no blur, no glow. R-12: about 3 shadows per screen, all for elevation.
- R-35 verification: build, string check, 398 tests (UTC and Asia/Jakarta), browser check and CI run on every push.
- Copy: 0 em dashes in prose, 0 buzzwords, 0 generic CTAs, 0 apologetic phrases in 1,737 strings.
- Code: no AI-voice comments, no TODOs, comment density 11%, comments explain why.
