# Anti-Slop audit 001 (2026-11-02)

Scope: the whole app: UI (`src/ui`), copy (`i18n.js`), styles, the logic and Apps Script code (`src`), the dev scripts, the docs.
Rules: miqdadbadjuber/anti-slop (R-01 to R-40, tiers: Hard Gate = HIGH, Purpose-Gate = MEDIUM, Quality Locks = LOW) and b4r7x/agent-skills anti-slop (code categories). The rule text was read through a summarising fetch, so rule numbers and meanings are cited, not quoted.
Method: 48 rendered screens (24 screens x phone and PC, demo data, headless Edge) measured for tap targets, overflow, focus visibility and decoration; axe-core in light and dark (earlier today: 0 problems); static checks over copy, CSS and code (`scripts/antislop-static.mjs`, `scripts/antislop-browser.mjs`); a manual read of the claims in the copy.
Not covered: real devices, a screen reader, the real data's long-tail screens, Quest Board and the other projects.

Nothing has been changed. Pick numbers to fix.

## Refinements from style.ai.id (2026-11-02)

style.ai.id is a directory of UI tools, not a design system, so nothing was adopted whole: most of its libraries are React and this app is plain JavaScript on a page that may not load outside scripts. Six ideas that carry over were built. Each is checked by a test or a real-browser script.

| # | Refinement | Evidence and check |
|---|---|---|
| 1 | Motion tokens and a complete reduced-motion rule (idea: Transitions.dev flags hard-coded durations and a missing reduced-motion guard). Three durations and an easing curve became `--dur-quick`, `--dur-base`, `--ease-out`; the reduced-motion rule used to miss the arrow of the folded day card and now covers every transition and animation, present and future. | `test/motion.test.js`: no `transition: all`, no hard-coded duration or easing, the rule covers everything. |
| 2 | Pop-up focus. The page behind a pop-up is inert, focus moves in (the pop-up itself on a phone), Tab stays inside, and closing returns focus to what opened it, or to the page if that control was redrawn. Before: Tab left the pop-up, and on a phone focus did not move at all. | `src/ui/modal.js`; a UI test taps a row, checks the page is inert, wraps Tab and Shift+Tab, closes with Escape and checks focus is back on the row. |
| 3 | Messages stack (three at most, newest at the bottom) and each keeps its own Undo. Before: a second message replaced the first and its Undo was lost. | `test/toast.test.js`. |
| 4 | The design direction as a file an assistant reads first: a table of every token with its light and dark value, linked from the README. | `test/tokens.test.js` compares the table with the stylesheet in both themes and found, by design, a second risk: the dark palette is written twice in the stylesheet, so the test also checks the two copies are identical. Proved by breaking one value on purpose. |
| 5 | A sliding thumb on the Us / Me / name, Overview / Report and Monthly / Yearly switches (`transform` and `width` only, 120 ms, placed where it was across redraws). The add-form's wrapping kind selector is left alone. | `scripts/motion-check.mjs` in a real browser: the thumb eases 4, 51, 56, 56 px after a tap, and with reduced motion it is at the end at once. |
| 6 | Skeletons shaped like each screen's first blocks. Layout shift was already about 0 on all 48 screens (a swap replaces nodes rather than moving them), so the measure that mattered was where each block sits: the biggest offset was 22% of the window on Transactions and 86% on the Summary, with 337px empty at the bottom. | `scripts/skeleton-check.mjs`: now 3%, 0% and 0% on a phone and on a PC alike, nothing empty, and total layout shift over the 48 screens is 0.008. |

Not adopted, with reasons: component libraries (React; no outside scripts), background and shader generators (against the direction), counting, flipping and tilting effects (too lively for a money app).
